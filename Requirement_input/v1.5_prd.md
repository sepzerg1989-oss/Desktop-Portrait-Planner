## 2. 顶栏导航与巨型悬浮面板需求

为了追求空灵、留白的艺术画廊观感，Header 导航将化繁为简，并引入高奢的微交互体验。

### 2.1 顶栏结构精简
- **导航入口**：顶部 Header 仅保留**两个主入口**，居中排版：
  1. **【我的策划】**：直接跳转至 `/` (策划大厅 Dashboard.vue)。
  2. **【素材档案 ▾】**：鼠标悬浮或点击时，向下展出巨型悬浮面板。
- **全局设置**：保留在 Header 右侧的胶囊动作区域。

### 2.2 【素材档案】巨型悬浮面板 (Mega Panel) 规范
- **布局结构**：采用 `flex` 布局，背景为 `bg-morandi-paper`，严禁使用任何实线边框，仅采用极低透明度弥散阴影 `shadow-[0_25px_50px_-12px_rgba(0,0,0,0.05)]` 托起。
  - **左侧 (2/3 宽度) 文字目录**：分为 2 列，严格使用语义化颜色（bg-morandi-paper, text-morandi-text）：
    - **第一列 (人物与造型)**：`01 模特档案`、`02 妆面造型`、`03 服装搭配`
    - **第二列 (空间与物品)**：`04 场地堪景`、`05 道具中心`
    - *排版细节*：序号使用小号、低透明度的数字（如 01, 02），主文字使用优雅的衬线体（font-serif），鼠标悬浮时背景为 `hover:bg-morandi-text/5`，字色加深。
  - **右侧 (1/3 宽度) 摄影艺术橱窗**：一个比例修长的容器（如 `w-72` 或 `w-80`），放置垂直构图的艺术摄影作品。
- **微交互升级 (WOW Point)**：
  - 当鼠标悬浮在左侧不同的目录项（如“01 模特档案”、“02 妆面造型”等）上时，右侧橱窗图片**智能且丝滑地切换**至对应的主题艺术摄影作品（切换速度建议 `duration-500` 配合淡入淡出效果）。
  - 图片拥有 `transition-transform duration-700 hover:scale-105` 的轻柔缩放效果。
- **跳转路由映射**：
  - `01 模特档案` ➡️ `/models`
  - `02 妆面造型` ➡️ `/makeup` (NEW)
  - `03 服装搭配` ➡️ `/clothing` (NEW)
  - `04 场地堪景` ➡️ `/locations`
  - `05 道具中心` ➡️ `/props` (NEW)

## 3. 三大新增资源库视觉与数据规范

为避免信息过载并提供极致的录入与浏览体验，数据字段采取“外层极简展示，内层详情查看”的策略，并根据物理与情绪属性进行分类设计。

### 3.1 封面提取规则（化繁为简）
- **通用原则**：服装库、道具库、妆容库**取消独立封面图上传控件**，默认自动提取并渲染相册图片列表（`images_json`）中上传的**第一张图片**作为封面。

### 3.2 道具库 (`props`) & 服装库 (`clothing`) —「博物学图鉴 / 高端 Lookbook 风格」
- **设计理念**：不使用拍立得白边。将道具与服装视作高奢博物馆馆藏或时装周单品，使用纯边框、纯平的高端画册排版，卡片和参数沉浸在 `bg-morandi-paper` 材质上。
- **图片宽高比**：
  - **道具卡片**：图片锁定 **1:1** 完美正方形尺寸。
  - **服装卡片**：图片锁定 **3:4** (或 **2:3**) 竖幅黄金艺术比例。
- **数据字段精简**：
  - `id`：主键自增。
  - `name`：名称（如 "中古包豪斯钢管椅" / "赫本风复古黑裙"）。
  - `description`：描述/穿搭说明。
  - `tags`：标签 JSON 数组（如 `["中古", "冷调"]` / `["赫本风", "丝绒"]`）。
  - `link`：购买链接/租用渠道（非必填）。
  - `price`：价格/租金（非必填）。
  - `images_json`：相册（多张图路径）。
  - `created_at`：添加时间（用于默认倒序排列）。
- **页面展示逻辑**：
  - **外层卡片墙样式（极简还原样图）**：仅展示 **图片、名称、描述、Tags**。
    - 图片下方第一行：`[名称] / [Tag 1] · [Tag 2]`（字号 `text-[10px]`，中间用 ` / ` 及中点隔开，全部大写/英文高档感）。
    - 第一行下方第二行：`[描述]`（超长文本自动以 `...` 截断，单行排列）。
  - **详情侧拉抽屉 (Drawer)**：仅当点击进入查看或在编辑器中被调用时，才渲染展示 **价格** 与 **购买链接**。

### 3.3 妆容库 (`makeup`) —「拍立得 Mini 情绪相卡风格」
- **设计理念**：妆容代表“情绪”、“风格捕获”与“艺术创作”，与模特库类似。采用经典的 **富士拍立得 mini 相纸风格 (Polaroid Mini Frame)**，卡片周围带有一圈微弱的、底部较宽的复古艺术白边。
- **数据字段精简**：
  - `id`：主键自增。
  - `name`：名称（如 "慵懒日杂感裸妆"）。
  - `description`：妆容说明/彩妆重点。
  - `tags`：标签 JSON 数组（如 `["清透", "哑光"]`）。
  - `images_json`：多张特写细节相册。
  - `created_at`：添加时间。
- **页面展示逻辑**：
  - 卡片呈拍立得白边托起，相纸内填充首图，白底底部印刻优雅的衬线体手写名称与标签分类。

## 4. 策划编辑器双向联动与横向排版需求

升级后的编辑器支持在单模块中管理“多服装/多道具”项，极大地提升策划排版的精细度。

### 4.1 策划模块结构调整
- **新增模块**：策划案画布支持添加 `makeup` (妆容造型) 模块，与已有的服装、道具模块等同。
- **多绑定能力（多套Look/多组道具）**：
  - `clothing` (服装模块) 与 `props` (道具模块) 的 `data` 结构从“单条绑定”升级为 **多值绑定数组 (items)**，支持用户在一个模块里，一键导入多个库内服装或道具项。

### 4.2 模块画布渲染 —— 💡「Lookbook 横向联席流」
- **画布展示效果**：
  - 在 Canvas 渲染页面，服装/道具模块以 **横向平铺卡片流（Horizontal Grid Row）** 呈现。
  - 每个绑定的服装或道具展现为一个极其考究的 **Mini 视觉卡片**：
    - 上方/左边为无边框小图（道具为 1:1 小正方形，服装为 3:4 竖幅）。
    - 下方/右侧为极小字号的 `名称 / 描述 / 标签` 裸排信息。
  - 支持多张卡片并列，横向超出时支持优雅微弱的物理滚动（Horizontal Scroll）或整齐换行，纵向占用高度极小，完美节省纵向空间，彰显专业的时尚杂志排版质感。
  - 妆容模块 (`makeup`) 在 Canvas 上则以精美拍立得卡片形式单张/多张陈列。

### 4.3 编辑器双向联动逻辑
- **一键导入（正向）**：
  - 编辑策划案时，点击服装/道具/妆容模块属性面板上的“从素材库导入”按钮，弹窗拉出精致的资源库筛选面板。
  - 勾选所需项后，一键将数据与图片路径克隆并解耦复制写入当前策划模块。
- **一键存库（逆向）**：
  - 在当前策划里直接上传/编写的服装、道具或妆容内容，在其属性面板上拥有“+ 快速保存至素材库”按钮，输入姓名后即可一键将其克隆沉淀到全局的素材库中。

## 5. 技术与数据底层改造方案

### 5.1 数据库结构升级 (SQLite3 `database.sqlite`)
在 `DatabaseService.js` 中新增三张业务表，表字段严格对应：

```sql
CREATE TABLE IF NOT EXISTS clothing (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  description TEXT DEFAULT '',
  tags TEXT DEFAULT '[]',
  link TEXT DEFAULT '',
  price TEXT DEFAULT '',
  images_json TEXT DEFAULT '[]',
  created_at TEXT DEFAULT (datetime('now','localtime'))
);

CREATE TABLE IF NOT EXISTS props (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  description TEXT DEFAULT '',
  tags TEXT DEFAULT '[]',
  link TEXT DEFAULT '',
  price TEXT DEFAULT '',
  images_json TEXT DEFAULT '[]',
  created_at TEXT DEFAULT (datetime('now','localtime'))
);

CREATE TABLE IF NOT EXISTS makeup (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  description TEXT DEFAULT '',
  tags TEXT DEFAULT '[]',
  images_json TEXT DEFAULT '[]',
  created_at TEXT DEFAULT (datetime('now','localtime'))
);
```

并在 `DatabaseService.VALID_TABLES` 和 `VALID_COLUMNS` 中完成映射声明，确保极高的数据安全校验。

### 5.2 Preload API 通信层暴增接口
在 `preload.js` 的 `electronAPI` 下，纵向扩展三大资源库的高吞吐 CRUD 桥接接口：
- `electronAPI.getClothings()`, `createClothing()`, `updateClothing()`, `deleteClothing()`, `deleteClothingsBatch()`
- `electronAPI.getProps()`, `createProp()`, `updateProp()`, `deleteProp()`, `deletePropsBatch()`
- `electronAPI.getMakeups()`, `createMakeup()`, `updateMakeup()`, `deleteMakeup()`, `deleteMakeupsBatch()`

### 5.3 数据备份包导入/导出服务升级 (Data Exchange Update)
- **前端 `DataExchangeModal.vue` 升级**：
  - 数据导出弹窗新增三个标签页（Tab）：【服装搭配】、【道具中心】、【妆容造型】。
  - 数据模型 `selections` 中扩充 `clothing`、`props`、`makeup` 的选中状态。
  - 在弹出时异步调用对应的 Pinia store 加载所有记录并自适应展示。
  - 勾选所选项目后，合并到导出参数中传递给 `window.electronAPI.exportData()`。
- **主进程 `ExportService.js` 升级**：
  - `exportData(ids, win)` 支持解析 `clothingIds`、`propsIds`、`makeupIds`。
  - 读取并打包服装、道具、妆容的 SQLite 记录，并抓取 `images_json` 列表中的第一张图及全部图册物理图片转化为 Base64 格式写入 `.ppexport` 数据包中。
  - `importData(win, filePath)` 支持解压并反序列化这三张表的数据，保存其 Base64 图片资产到当前工作区的 `images/imported` 目录中，并将 SQLite 记录写入新表中。

## 6. 验证与验收标准

### 6.1 视觉与排版验收
- **博物学排版**：道具与服装卡片的图片无拍立得白边，道具固定 1:1，服装固定 3:4。下方的参数用 ` / ` 优雅排布。外层绝对不显示链接与价格。
- **拍立得妆容卡片**：妆容列表卡片完全符合底部宽、周围窄的拍立得 mini 结构。
- **横向 Lookbook**：在策划案中添加 3 件服装后，Canvas 中的服装模块需以横向卡片流形式平铺展示，不产生无限的纵向延展。

### 6.2 状态联动验收
- **首图默认封面**：在各库中上传多张图后，列表自动提取首张图进行卡片展示；变更图集顺序后封面图响应式发生改变。
- **导入与导出**：策划编辑器内可成功从服装/道具/妆容弹窗中勾选多项并复制到模块内。策划案一键导出高清长图时，所有横向联展卡片及拍立得卡片正常渲染显示。
